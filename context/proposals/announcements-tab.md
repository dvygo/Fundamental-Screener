# Proposal — an Announcements tab, on TrueWealth's terms

**Status: proposed, not built.** Prompted by wealth.truedata.in.

## What they do that we don't

TrueWealth's headline is **real-time corporate announcements with an AI verdict**
per announcement — Strong Positive / Positive / Negative / Strong Negative /
Mixed / Neutral — filterable by date, index and sentiment. Around it: a calendar,
peer comparison in several view formats (Basic, Intrinsic Value, Heatmap,
Ratios, Comprehensive), full P&L / balance sheet / cash flow, and shareholding.

## We already collect the input, and nothing reads it

Every NSE daily drop contains `an<DDMMYYYY>.txt`. Measured 2026-08-20:

    73 files already on disk, 136,263 announcement lines
    ~2,584 per trading day
    format:  <Company Name> <SYMBOL> : <announcement text>

Nothing in `src/python/`, `src/nodejs/` or the UI touches it. It is extracted by
`extract.py` and then ignored — the same state `shareholding_facts.parquet` was
in before it got a producer.

That makes this the cheapest large feature available: no new source, no scraping
question, no robots.txt to check, no rate limit. It is a parser and a tab.

## Build order

**1. Parse and land it.** `an<date>.txt` -> a day-partitioned or consolidated
table (symbol, company, text, as_of). The symbol is embedded at the end of the
company name rather than in its own column, so splitting needs care — match the
trailing token against `security_master` rather than assuming the last word is
always the symbol.

**2. Categorise with rules, not a model.** Before reaching for sentiment, the
higher-value and more defensible step is bucketing: Acquisition, Fund Raise,
Order Win, Resignation, Rating Change, Monitoring Report, Routine/Compliance.
`corp_actions` already does exactly this with keyword rules over NSE's PURPOSE
field, so the pattern exists in the codebase. Most of the 2,584 daily rows are
routine compliance filings; the value is in filtering those OUT.

**3. Only then consider a verdict.** And if we do:

  **A sentiment verdict is an OPINION, and must be labelled as one.** Every
  other number in this app is traceable to a file an exchange published. A
  verdict is generated by us. Presenting it in the same visual register as a
  reported EPS would be the exact confusion the source lanes exist to prevent.
  It needs its own styling, and the methodology page needs a row saying plainly
  that this column is model output, not disclosure.

  This is the same discipline as HUNT's five honesty rules — a score is shown
  with its components so a reader can disagree with it. A one-word verdict with
  no visible reasoning is weaker than what the rest of the app already does.

**4. Tab.** `/announcements`, market: IN. Filters by date, category, symbol.
The India lane, since the source is NSE.

## What else from TrueWealth is worth taking

**Full financial statements.** They show annual P&L, balance sheet, cash flow.
We hold the XBRL to build these — `xbrl_populate.py` already shreds filing facts
losslessly — but nothing pivots them into statements. Bigger job than
announcements, higher ceiling.

**Peer comparison.** Their several view formats over a sector's constituents.
We have GICS sector on the US side and NSE's industry mapping on the India side,
so the grouping key exists.

**Not worth taking: the calendar**, unless corp_actions gets there first — we
already hold ex-dates and record-dates and render them as a table. A calendar is
a presentation change, not new data.

## Recommendation

Announcements first, and stop at step 2 for the first pass. A parsed, bucketed,
filterable announcements feed with the routine 80% suppressed is genuinely
useful on its own, ships without any model, and is the honest half of what
TrueWealth is selling.
